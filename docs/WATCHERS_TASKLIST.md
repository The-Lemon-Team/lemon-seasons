# 🔭 Watchers: Автономные локальные слушатели и сбор новостей

> **Статус**: Запланировано на будущее (Future Backlog / Vision)  
> **Проект**: Lemon Calendarium / Project Lenta — Подсистема `Watchers`  
> **Роль компонента**: Собственная локальная альтернатива и дополнение к Gemini Spark для мониторинга интернет-источников, сбора новостей и автоматической генерации `.md` файлов.

---

## 1. Контекст и мотивация

В текущей архитектуре Lemon Calendarium основным поставщиком внешних дайджестов и новостей является автономный конвейер **Gemini Spark**: боты формируют структурированные `.md` заметки, складывают их в облачные/локальные папки, после чего сервис `SparksParserService` инжестит их в базу данных и распределяет по контейнерам Obsidian и табам ленты.

**Проблема**: Зависимость от стороннего облачного решения Spark ограничивает гибкость источников (например, закрытые каналы, специфичные новостные ленты, локальные парсеры).

**Цель проекта Watchers**:
Создать собственную независимую систему прослушивания ("Watchers"), работающую автономно на домашнем компьютере. Система должна непрерывно отслеживать выбранные интернет-источники, упаковывать новости по расписанию в markdown-заметки (аналогично Spark) и предоставлять наглядный интерфейс контроля статуса слушателей.

---

## 2. Ключевые требования (Core Requirements)

```
│                       АРХИТЕКТУРА СИСТЕМЫ WATCHERS                          │

│                            │                                                │
│                            ▼                                                │
│  [ Watchers Core Daemon ] (Домашний ПК / Выделенный сервис)                  │
│   ├── Адаптеры источников (TelegramWatcher, RssWatcher, WebWatcher)         │
│   ├── Локальная БД состояния (SQLite / DuckDB / JSON cache)                 │

│   └── Шедулер (Cron / Interval triggers)                                    │
│                            │                                                │
│            ┌───────────────┴───────────────┐                                │
│            ▼                               ▼                                │
│  [ Генератор .md заметок ]     [ Control Plane / UI ]                       │
│   • Совместимость со Spark       • Список всех воркеров                     │
│   • Frontmatter метаданные       • Статус: RUNNING / STOPPED / IDLE / ERROR │

│            │                     • Кнопки Старт / Стоп / Run Now            │
│            ▼                                                                │

│   └── Попадание в ленту и контейнеры Obsidian                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **Локальный сбор с домашнего компьютера (Home PC Edge Agent)**:
   - Автономный фоновый сервис/демон, работающий локально.
   - Минимальное потребление ресурсов, отказоустойчивость при разрывах сетевого соединения.

2. **Мульти-источники (Pluggable Listeners)**:
   - **Telegram**: Прослушивание публичных/приватных каналов, чатов и веток.
   - **RSS / Atom**: Периодический поллинг RSS-фидов блогов, новостных агрегаторов и медиа.
   - **Веб-сайты (Web Scrapers)**: Мониторинг веб-страниц без RSS через селекторы контента и детектирование новых статей.

3. **Генерация заметок и доставка по расписанию (Spark-compatible Pipeline)**:
   - Подача новостей порциями по расписанию (утренний дайджест, дневной срез, вечерняя сводка) либо по накоплению порога событий.
   - Формирование Markdown-файлов формата, идентичного Gemini Spark:
     ```markdown
     ---
     title: "Заголовок новости"
     date: 2026-10-22T09:00:00Z
     source: "telegram:@channel_name"
     tags: [news, tech, ai]
     original_url: "https://t.me/..."
     watcher_id: "tg-tech-news"
     ---
     # Краткая суть
     ...
     ```
   - Прямой экспорт в отслеживаемые папки Lemon Calendarium (`uploads/notes/` или Google Drive sync).

4. **Интерфейс управления и мониторинга (Watchers Dashboard)**:
   - Единое приложение / экран со списком зарегистрированных слушателей.
   - Отображение статуса в реальном времени:
     - 🟢 **Running** (активен, прослушивает)
     - ⏸️ **Paused / Stopped** (приостановлен)
     - 🔴 **Error** (сбой соединения / rate limit / невалидный селектор)
     - ⏳ **Scheduled** (ожидает триггера расписания)
   - Метрики: время последней проверки, количество собранных постов, размер очереди.
   - Элементы управления: Запустить / Остановить / Проверить сейчас (Trigger manually).

5. **Изоляция проекта (Отдельная папка / Репозиторий)**:
   - Выделение кода в отдельную директорию в монорепозитории (например, `apps/watchers`) либо в отдельный Git-репозиторий (`lemon-watchers` / `lenta-watchers`).
   - Независимый стек запуска, свои зависимости и конфиги окружения.

## 4. Детализация этапов

### 📁 WATCH-01: Изоляция и структура проекта (Scaffolding)
- **Цель**: Выделить модуль слушателей в чистый автономный контур.
- **Шаги**:
  1. Выбор формы размещения: подпапка `apps/watchers` в текущем монорепозитории pnpm/turbo или внешний репозиторий.
  2. Базовый шаблон сервиса (Node.js/TypeScript или Python FastStream/APScheduler).
  3. Конфигурация через `.env` (токены, пути к выходным папкам, интервалы).
  4. Скрипты локального запуска демона на домашней машине.

---

### ⚙️ WATCH-02: Ядро воркера и локальный шедулер (Core Engine)
- **Цель**: Обеспечить надежное выполнение фоновых задач по расписанию и отслеживание жизненного цикла.
- **Шаги**:
  1. Абстрактный интерфейс `BaseWatcher` (`id`, `name`, `sourceType`, `status`, `start()`, `stop()`, `poll()`).
  2. Локальное хранилище состояния и истории просмотров (SQLite / JSON-файлы) для предотвращения дублирования новостей.
  3. Шедулер с поддержкой Cron-выражений (например: `"0 8,13,20 * * *"` для утренних, дневных и вечерних сводок).
  4. Механизм повтора при сбоях сети (Retry policy с экспоненциальной задержкой).

---

### 📡 WATCH-03: Слушатель RSS / Atom лент
- **Цель**: Надежный сбор новостей из классических RSS/Atom фидов.
- **Шаги**:
  1. Модуль парсинга фидов (заголовки, контент, pubDate, GUID).
  2. Валидация и нормализация HTML-текста в чистый Markdown.
  3. Фильтрация по стоп-словам или ключевым темам.

---

### 💬 WATCH-04: Слушатель Telegram-каналов
- **Цель**: Получение постов из новостных каналов Telegram.
- **Шаги**:
  1. Реализация клиента (Telegram Bot API с вебхуками/поллингом либо Telegram MTProto User API / Telethon для каналов без ботов).
  2. Извлечение текста, ссылок, медиа-описаний и вложенных сообщений.
  3. Буферизация постов в локальный пул до наступления времени отправки дайджеста.

---

### 🌐 WATCH-05: Слушатель веб-сайтов (Web Scraper)
- **Цель**: Мониторинг новостных сайтов без RSS.
- **Шаги**:
  1. Скрапер на базе Cheerio (легковесный) или Playwright (для SPA с JavaScript-рендерингом).
  2. Декларативная настройка правил селекторов (CSS/XPath: контейнер статьи, заголовок, дата публикации, текст).
  3. Обнаружение изменений (diff хешей контента).

---

### 📝 WATCH-06: Пайплайн сборки .md файлов (Spark-совместимость)
- **Цель**: Формирование файлов заметок, готовых к прозрачному потреблению в Lemon Calendarium.
- **Шаги**:
  1. Форматирование frontmatter (теги, метаданные источника, временная метка, watcherId).
  2. Структурирование тела заметки: заголовок, краткая выжимка (TL;DR), полный текст, ссылка на первоисточник.
  3. Атомарная запись в целевую директорию инжеста (запись во временный файл + rename во избежание частичного чтения сервисом календаря).

---

### 🖥️ WATCH-07: Панель мониторинга и статусов (Watchers UI)
- **Цель**: Удобный визуальный интерфейс для контроля всех прослушивателей.
- **Шаги**:
  1. Экран управления слушателями:
     - Карточки/таблица воркеров (Имя, Источник, Расписание, Статус).
     - Цветовая индикация активности (зеленый пульсирующий бейдж — активен, серый — остановлен).
     - Лог последних событий (Last run, items collected, errors).
  2. Быстрые действия: тумблер On/Off для каждого слушателя, кнопка принудительного триггера `Run Now`.
  3. Форма добавления/редактирования нового слушателя (выбор типа источника, URL/канал, интервал).

---

### 🔗 WATCH-08: Сквозная интеграция с Lemon Calendarium
- **Цель**: Бесшовная связка с существующими сервисами календаря.
- **Шаги**:
  1. Настройка сопоставления тегов воркеров с контейнерами Obsidian (`ObsidianContainer`).
  2. Автоматическое распределение новостей Watchers по соответствующим табам unified feed.
  3. End-to-end верификация: от появления новости в Telegram/RSS до отображения в календаре.
